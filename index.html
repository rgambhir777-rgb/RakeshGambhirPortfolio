Focus areas

Where AI projects fail quietly, and where I specialise.

01 / agents

Agentic systems

Agents that call tools, plan over several steps and hand off to humans when they should.

  • Tool design, guardrails and permission boundaries
  • Trajectory and step-level evaluation, not just final answers
  • Failure recovery, retries and loop detection

Token spend treated as an engineering metric, with owners and budgets.

  • Prompt caching, context trimming, model routing
  • Budget alerts and per-feature cost attribution

LLM observability

Seeing what the model and agent actually did, why, and what it cost.

04 / trust

Accuracy, bias & hallucination management

Trust is designed and measured, not hoped for. I define what "correct" means with the customer, then make it testable.

  • Golden datasets and rubric-based LLM-as-judge, calibrated against human labels
  • Groundedness and citation checks for RAG; hallucination rate tracked per release
  • Bias and fairness evaluation across user segments, with documented thresholds
  • Red-teaming, prompt-injection testing and safe-refusal behavior

Forward Deployed Engineering

Embedded with the customer. Accountable for the outcome.

A Forward Deployed Engineer works where the problem is: in the customer's data, constraints and workflows. I bring all five focus areas into one engagement, so the result is a system the customer can run, measure and trust after I hand it over.

  1. 01

    Discover

    Map the workflow, the data and the real cost of a wrong answer. Agree on what success means.

    success criteria & risk map
  2. 02

    Prototype

    Build the smallest agent or LLM flow that proves value on real customer data.

    working agent + baseline evals
  3. 03

    Harden

    Test for accuracy, bias and hallucination. Add guardrails, then optimise tokens and latency.

    eval suite & cost model
  4. 04

    Deploy

    Ship behind automated quality gates, with tracing and dashboards in place from day one.

    CI gates & observability
  5. 05

    Operate & hand over

    Monitor drift and spend, run regressions, and train the team to own it.

    runbooks & team enablement

An FDE's job isn't finished at the demo. It's finished when the customer trusts the system without me in the room.

Approach

Measure first. Then ship, then keep measuring.

✓ assert release.evaluated

If it isn't evaluated, it isn't done

Every prompt, model or tool change runs against a versioned eval set before it reaches users. Quality is a gate, not an afterthought.

✓ assert cost_per_task <= budget

Cost is a quality attribute

A correct answer that costs ten times too much is a failed release. Tokens, latency and accuracy are tracked together.

✓ assert every_step.traced

Observable by default

Every agent step is traced and every failure is explainable. When something goes wrong, the team can see why in minutes.
